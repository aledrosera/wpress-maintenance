# Phase: media

## Objective
Only the media the site uses (principle 8), each one optimized.

## Determine
- Usage from the covered real visits (baseline data plus what changed): files requested, every upload reference in the DOM (sources, responsive sets, posters, data attributes, inline styles), in inline scripts and in all CSS rules of every breakpoint. Map responsive and modern-format variants back to their attachment.
- References outside public pages, for the whole site: attachment identifiers and file names in content of every status, in post, term and user meta, options, widgets, builder data, commerce data and code. A reference there is use, even if no visit shows it.
- Files generated by builders from an attachment, and the attachment each one depends on.
- Where media are served from (site profile): references to the production domain or a media host map to local files with the same path; media stored only outside the archive are out of reach: record them, leave their references alone.
- Cross-check: every media file the matching live pages use exists locally.
- Weight: totals by type, largest files, already optimized files, video codec, resolution, bitrate, duration and audio, and how each video is embedded (preload, autoplay, controls).

## Decide
- Delete only attachments with no reference of any kind; an ambiguous reference keeps the attachment and goes in the report. Orphan files are media files in the dated upload folders with neither attachment nor reference; folders owned by a component stay unless cleanup removed that component.
- For attachments in use, remove the generated sizes nothing references and update their metadata so WordPress never outputs a missing file; keep the main file. Stop generating sizes the site never uses, with a setting that travels with the site.
- Recompress images keeping names, paths, dimensions and colour profile; the result is visually indistinguishable at the largest displayed size (checked on a sample) and smaller by a margin worth a re-encode; already optimized files are left alone; strip only metadata that is not rights, credits or colour. Modern-format variants only where the site already serves them, and only where smaller.
- Videos: a codec and container that play in every major browser and device, a bitrate suited to resolution and use, fast start, no audio track for background videos; keep the result only when materially smaller.
- Unused media are deleted whatever their upload date; recent ones are listed in the report.
- Processing tools are installed temporarily inside a container and removed at the end.

## Risks to check
- Builder-generated files depend on the original attachment: deleting it breaks their regeneration.
- Media used only on interaction (lightboxes, later slides) are in the DOM: DOM references count as usage.
- A video with automatic full preload is downloaded entirely when the page opens.
- Name prefixes collide: match media names exactly.

## Exit criteria
The references of every covered URL and the database references resolve to existing files; every media file used by the matching live pages exists locally; weight before and after is measured.

## Report
Attachments, files and upload size before/after; what was deleted and what was kept on an ambiguous reference; compression choices; video changes; media out of reach.
